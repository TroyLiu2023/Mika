## ADDED Requirements

### Requirement: 启动 App 后交给模型的画面来自该次启动之后

启动一个 App 成功后，读屏附带画面、单独截图、动作后的回看画面，必须来自该次启动开始之后虚拟屏收到的渲染帧；上一屏留下的残影不得当作新画面交给模型。

#### Scenario: 新帧及时到来
- **WHEN** 启动成功、界面稳定后，虚拟屏在时限内收到晚于启动开始时刻的新帧
- **THEN** 截图/回看返回该新帧，行为与现在一致

#### Scenario: 新帧迟迟不来
- **WHEN** 启动成功后到时限仍没有晚于启动开始时刻的帧（首帧渲染慢、卡在启动页合成等）
- **THEN** 启动收尾多等一段有界时间；仍没有时，保护窗内截图口返回「无画面」（读屏退化纯文本、单独截图报 screenshot_unavailable），不返回旧帧

#### Scenario: 保护窗过期
- **WHEN** 启动后超过保护窗仍无新帧
- **THEN** 截图口恢复返回现有最新帧（长时间运行中不能永久拿不到画面）

#### Scenario: 与启动无关的截图不受影响
- **WHEN** 没有刚发生过的启动（普通浏览、滚动后的截图）
- **THEN** 行为与现在完全一致

### Requirement: 等待与判定的逻辑在 JVM 上可测

帧新鲜度的等待与截图保护窗的判定是纯逻辑：时钟、等待、最新帧时刻、启动时刻都由调用方注入，电脑上单测覆盖边界。

#### Scenario: 单元测试
- **WHEN** 以注入的假时钟与假帧时刻运行
- **THEN** 各分支（等到新帧/超时/无启动/保护窗过期）行为可断言
