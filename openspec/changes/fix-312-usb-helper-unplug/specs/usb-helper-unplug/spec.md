## ADDED Requirements

### Requirement: 启动脚本的提示不无条件承诺拔线后继续运行

`usb-start.sh` 的输出必须与设备实际行为一致：不得在所有设备上无条件输出「拔掉数据线也能继续用」一类的承诺。

#### Scenario: 未观察到拔线回收的设备
- **WHEN** 本机没有学到「拔线回收助手」的标志，脚本启动助手成功
- **THEN** 提示措辞不打包票（说明多数手机上拔线后助手继续运行；若手机操作停了，重新插线再运行一次本命令即可恢复）

#### Scenario: 已观察到拔线回收的设备
- **WHEN** 本机已学到「拔线回收助手」的标志，脚本启动助手成功
- **THEN** 输出如实说：这台手机拔掉数据线会停掉助手；重新插线后再运行一次本命令即可恢复手机操作

#### Scenario: 助手没起来时的指引保持现状
- **WHEN** 脚本启动助手失败
- **THEN** 指引保持「先打开一次 Mika，再运行本命令」（打开 Mika 会顺带换新口令；不做按进程存活区分的变体——失败分支罕见，区分并不改变该指引的有效性）

### Requirement: 学到「本机拔线回收助手」的标志

App 运行期间把电源断开事件记下时间；「用电脑启动」的助手（未配对）在其后的一小段关联窗口内死掉时，持久化记下该标志。标志描述的是这台手机系统的行为，解除配对不清除。

#### Scenario: 时间关联成立
- **WHEN** 助手由 USB 启动（未配对）、Mika 进程存活，电源断开后的关联窗口内助手死亡
- **THEN** 持久化「拔线回收助手」标志，此后的脚本文案与设置页提示按该标志切换

#### Scenario: 无关的助手死亡不立标志
- **WHEN** 助手死亡时附近没有电源断开事件（或超出关联窗口）
- **THEN** 不设置标志，文案保持默认

### Requirement: 学习到标志后界面提示如实

设置 › 手机操作 的说明、引导成功页的提示，在标志置位后不得再说「拔掉数据线也能继续用」，要说拔线会停、插线后重跑一次命令即恢复。

#### Scenario: 设置页提示
- **WHEN** 标志已置位且助手是用 USB 命令启动的
- **THEN** 用法说明/成功页提示包含拔线会停、重跑命令恢复的说法
