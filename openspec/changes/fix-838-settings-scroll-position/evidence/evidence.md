## 2. 修复过程中的两次偏差（都定位到了原因）

### 2.1 第一版（只提升滚动状态）：首页好了，别的页在底部有偏差

首页滚到「语言与外观」y=1273，进子页，返回箭头 / 系统返回键回来都是 1273（文件 321、偏好 805、数据 1959
逐像素一致）。但从「高级与其他」「任务运行」的底部往返时：

| 页面 / 操作 | 离开前 | 返回后 | 差 |
| --- | --- | --- | --- |
| 高级与其他滚到最底 → 恢复与修复 → 返回（`12-without-restore-advanced-bottom-after-back.png`） | 环境变量 546 | 环境变量 618 | +72px（24dp） |
| 高级与其他停在中间 → 恢复与修复 → 返回 | 环境变量 999 | 环境变量 999 | 0 |
| 任务运行滚到底 → 按应用设置 → 返回（`10-without-restore-duringwork-after-back.png`） | 直接操作小画面 957 | 直接操作小画面 1517 | +434px |

原因（代码 + 实测对照）：简约列表的卡片脚注是行在 `SideEffect` 里登记、下一帧才画出来的
（`Surfaces.kt` 的 `rememberCardNote` / `GroupCard`），页面首帧内容偏矮、缺全部脚注。带着位置回来时，
位置不在底部则滚动值不被截（首帧行偏高一帧，脚注出现后复位，最终一致）；位置靠近底部则
`ScrollState` 在首帧布局里按偏小的上限把值截短，脚注出现后不会自己补回。高级与其他只有一个脚注
（72px = 一个脚注行），任务运行有很多个（合计 434px）；首页最后两张卡没有脚注，所以首页到底也一致。
把「高级与其他」滚回顶部再与首次进入对比，截图逐像素相同，排除了「页面内容变了」。

### 2.2 第二版（加截短补救，但位置在效应协程里读）：补救没生效

任务运行到底 → 按应用设置 → 返回：直接操作小画面 957 → 1517，仍差 434px。原因是「带着的位置」在
`LaunchedEffect` 的协程体里读，而协程是派发后才跑的，那时首帧布局已经把值截短，读到的就是截短后的值，
判定成「没被截短」。

### 2.3 第三版（位置在组合里读）：全部一致

`PageScaffold` 用 `remember(scroll) { scroll.value }` 在组合阶段记下带着的位置，首次布局后若值变小且
正落在当前上限上，等上限长回去（≤500ms）且期间值没被动过，再 `scrollTo` 回去。

## 5. 操作中踩到的坑（记下来免得重犯）

- `adb install -r` 之后立刻 `am start`，会和系统包替换的收尾（`Force stopping … pkg removed`）撞上，
  刚启动的 Activity 被清掉、前台变成别的应用。安装和启动要分开，中间留几秒。
- 调试包的增量打包会在 APK 里留下被重写 dex 的旧副本（每构建一次涨约 3MB），中央目录只引用当前条目，
  不影响运行；判断「修复进包没有」要查 dex 里的类，不能看包大小。
- 这个 ROM 的聊天首页有持续滚动的示例气泡，`uiautomator dump` 取不到 idle 状态；设置页没有动画，可以取。
