## ADDED Requirements

### Requirement: 从子页返回时停在原来的滚动位置

设置页内，有子页可进的页面（首页、高级与其他、任务运行、恢复、开发者选项）在进入子页再返回后，
MUST 停在离开时的滚动位置，不得回到顶部。换界面语言页面重建、进程被回收后恢复时，这些页面的位置
MUST 接上重建前的值，与页面未离开组合时一致。

#### Scenario: 首页滚到偏好一带再进子页返回
- **WHEN** 用户在设置首页往下滚到「偏好」一带，点开「语言与外观」，再返回（顶栏返回箭头或系统返回）
- **THEN** 首页仍停在原来的位置，「语言与外观」还在离开前的地方

#### Scenario: 二级页再进三级页返回
- **WHEN** 用户在「高级与其他」往下滚，点进「沙箱」（或恢复、电脑访问、开发者选项等任一子页），再返回
- **THEN** 「高级与其他」停在离开时的滚动位置

#### Scenario: 停在页面底部时进子页返回
- **WHEN** 用户在「任务运行」滚到接近底部，点进该页底部的「按应用设置」，再返回
- **THEN** 「任务运行」停在离开时的位置；页面底部那些晚一帧才画出来的卡片脚注不得让它停在偏离处

#### Scenario: 页面重建
- **WHEN** 用户在设置首页滚到中间时换了界面语言（Activity 重建），或页面停在子页时进程被回收后恢复
- **THEN** 首页接上重建前的滚动位置

#### Scenario: 子页自身的状态不受影响
- **WHEN** 用户进入一个子页（如手机操作、AI 通话），做了操作后返回，再次进入同一子页
- **THEN** 该子页里原有的「每次进入重新开始」的状态（只问一次的提示、弹窗）行为与之前相同

### Requirement: 翻页期间滚动状态由切页的一方持有

用于切页显示的页面，其滚动状态 MUST 由翻页期间始终留在组合里的那一层持有（经 `PageScaffold`
的 `scrollState` 传入），不得只依赖页面自己组合里的默认滚动状态。

#### Scenario: 页面离开组合再回来拿到的是同一个状态
- **WHEN** 某页的滚动状态被取用过，随后其他页的状态被取用（相当于该页离开组合去了别的页），之后再次取用该页
- **THEN** 拿到的是同一个滚动状态，位置不变

#### Scenario: 不同页互不影响
- **WHEN** 两个不同页的滚动状态各自移动过
- **THEN** 各自的位置独立，互不覆盖

#### Scenario: 没有带滚动状态进来的页面不受影响
- **WHEN** 某页面经 `PageScaffold` 渲染但没有由切页的一方传入滚动状态
- **THEN** 它的滚动状态与截短补救都不参与，行为与之前相同
